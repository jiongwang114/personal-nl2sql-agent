## 二、当前已确认的问题

### 2.1 会话和输入能力

- [ ] 新建对话入口缺失：无法明确创建空白会话并重置当前上下文。
  - 验收：点击“新建对话”后，消息区清空、当前 session 清空、状态回到 idle，随后发送问题会创建新 session。
- [ ] 斜杠命令入口缺失：输入 `/` 时没有命令提示、选择或执行反馈。
  - 验收：命令列表来自已有后端/聊天协议；未知命令有稳定提示，不得伪造业务结果。
- [ ] Stop 后续对话被阻断：停止输出后没有补回可继续对话所需的 assistant 状态/事件，后续发送可能无法继续。
  - 验收：停止后消息结构完整、输入框可用；再次发送能建立新一轮请求，不重复或污染上一轮消息。
- [ ] 重试、恢复、新建、切换历史会话之间的状态边界不清晰。
  - 验收：每种操作都不会误清空其他会话，也不会复用错误的 session、event id 或消息列表。
- [ ] 会话加载、创建、切换、失败和空历史状态缺少统一反馈。

### 2.2 布局和视觉

- [ ] 用户输入框与聊天内容轴未完全对齐，宽度、左右边距或底部定位存在偏差。
  - 验收：桌面端消息列表、输入区、右侧面板的主要内容轴一致；不同窗口高度下输入区无需页面整体下滑即可看到。
- [ ] 页面首屏尺寸适配不足，输出窗口可能被推到首屏以下。
  - 验收：常见桌面分辨率下页面壳层占满视口，聊天内容和输入区在内部滚动；移动端保留合理自然滚动。
- [ ] 左右侧栏隐藏/恢复后，主聊天区宽度、输入区和输出面板没有充分验证所有状态。
- [ ] 视觉层级、空状态、错误状态和运行中状态不够统一，存在“功能存在但不可发现”的问题。
- [ ] 微交互需要逐项验收：按钮、卡片、链接和侧栏切换使用约 200–350ms ease-out，避免瞬时跳变、夸张缩放和厚重阴影。

### 2.3 运行上下文和 Agent 可观测性

- [ ] 上下文状态目前只显示 `message` 等泛化信息，不能区分当前事件类型。
- [ ] 未明确显示当前调用的是哪个子 Agent，例如 `schema-analyst`、`sql-generator`、`sql-reviewer`、`sql-debugger`、`result-interpreter`。
- [ ] 工具调用状态缺少清晰分层：工具名、参数、执行中、成功、失败、结果摘要应可区分。
- [ ] Extension 事件与普通 Agent 消息混在一起时，缺少来源标识和错误边界。
- [ ] MCP 调用缺少服务器、工具、连接状态和失败原因的稳定展示。
- [ ] Single / Multi 模式下的流程轨迹没有完整反映真实事件顺序，不能用静态文案代替后端事实。
- [ ] 模型、数据源、运行模式和当前 Agent 的选择状态需要与实际请求参数逐一核对。

### 2.4 错误、加载和空状态

- [ ] SSE 连接中断、HTTP 错误、业务错误、模型错误、工具错误和 MCP 错误需要统一映射为可读状态。
- [ ] 请求失败时必须保留当前用户问题和已有 assistant 输出，避免白屏或对话消失。
- [ ] 空数据源、无模型、无 Agent、无 MCP、无工具结果时需要明确空状态；不得注入伪造数据。
- [ ] 未登录/认证失效时需要保留页面结构并给出明确恢复路径。
- [ ] 长文本、代码块、工具参数和错误详情需要在窄屏下可读且不撑破布局。

## 三、实施顺序

1. [x] 先补齐会话状态机：新建、发送、停止、继续、重试、恢复、切换历史。
2. [ ] 再补齐事件模型：assistant、tool、sub-agent、Extension、MCP、error、completed 等来源和状态。
3. [ ] 然后修复布局约束和响应式尺寸，确保输入区与输出区首屏可见。
4. [ ] 最后完善视觉微交互、空状态、错误状态和可观测性细节。
5. [ ] 每个阶段完成后运行前端单测、构建、Playwright 和必要的后端接口回归测试。

## 四、完成标准

- [ ] 新建对话、斜杠命令、发送、停止、继续、重试、恢复、历史切换均可操作。
- [ ] 停止后再次发送不会因为缺失 assistant 消息而阻断。
- [ ] 聊天内容、输入框、左右面板在桌面和移动尺寸下均无明显错位或首屏遮挡。
- [ ] 上下文面板能准确显示事件来源、当前 Agent、工具/MCP/Extension 调用和状态。
- [ ] 真实后端数据驱动界面；缺失接口只显示稳定空状态和 TODO。
- [ ] Extension、工具调用、MCP 接入及 Pi Multi Agent 流程回归通过。
- [ ] 无明显白屏、控制台未处理异常或因前端状态错误导致的对话丢失。
