# 前端真实验收清单

> 目标：验证当前前端不是“页面能打开”，而是 Single/Multi 两条真实链路、设置、数据资源、会话和错误状态都能工作。测试不得用静态回答冒充成功。
>
> 证据：[frontend-next-02-evidence.md](../reports/frontend-next-02-evidence.md)；后续设置/导入/KB 验收见 [frontend-next-03-04-evidence.md](../reports/frontend-next-03-04-evidence.md)。未完整覆盖的项目保持未勾选。

## 1. 测试准备

- [x] 使用隔离测试数据源，优先 `sample_data/mf-demo.duckdb` 或项目当前已验证的只读 DuckDB；确认不会写入用户数据。
- [x] 启动后端和前端，记录实际端口、代码版本、Provider/模型、数据源、题目和会话 ID；密钥只通过环境变量/本机配置提供，不写入报告。
- [x] 先运行 API 直测，再启动浏览器；任一模式直测失败时，不把浏览器结果标为通过。
- [x] 测试服务重启后再测，避免静态前端或配置被旧进程缓存。

## 2. API 直测矩阵

- [x] `GET /health`：服务状态、数据库状态和模型状态分别记录。
- [x] `GET /api/v1/models`、`GET /api/v1/agent/list`、`GET /api/v1/catalog/list`：选择器数据与实际配置一致。
- [x] `POST /api/v1/chat/stream` 使用相同问题分别提交 `runtime_variant=single` 和 `runtime_variant=multi`。
- [x] 两条 SSE 都有 session、工具调用/结果、最终非空回答和 end；无未处理 error，且 SQL 与测试数据库预期结果一致。
- [x] `POST /api/v1/sql/execute` 执行同一条只读 SQL；`POST /api/v1/sql/stop_execute` 至少验证取消路径。
- [x] 记录成功、模型配额失败（隔离测试模拟 HTTP 403）、无效数据源和非法 SQL 的错误码/脱敏消息；错误不得被包装成成功。

## 3. 浏览器功能矩阵

### 核心工作台

- [x] 首屏加载会话列表，自动打开最近会话；无历史、空列表、接口失败都有明确状态。
- [x] 新建会话、发送、流式输出、后端停止、继续/重试、切换历史、刷新恢复均正常。
- [x] Single 与 Multi 选择值会进入真实请求；切换模式不会串用旧 session、事件游标或消息。
- [x] 页面显示工具名、参数摘要、工具结果、SQL、结果表、最终回答、Token/耗时和失败状态。
- [x] 用户交互弹窗按 SSE 问题渲染，HTTP 503 提交失败保留表单；最终回答缺失显示失败并可重试。
- [ ] 反馈提交按用户要求暂缓，前端不显示反馈入口。

### 设置和资源页面

- [x] 系统设置入口、模型列表、数据源列表、Agent 列表、MCP 状态、知识库入口可打开且不出现死按钮；Agent 工具目录使用真实 GET，MCP 页面只展示后端状态。
- [x] Catalog 数据库/schema 可用鼠标与键盘折叠，点击表刷新真实详情；空目录、HTTP 503 详情失败、窄表/宽表均有状态。
- [x] SQL 控制台执行、停止、空结果、错误和结果表均有可观察状态；不伪造独立历史、分页或排序。
- [x] 知识库构建使用真实 SSE 进度；浏览器完成 check 策略和隔离取消回放。
- [x] 平台文档导入浏览器回放包含必填校验、本地 Markdown 实际导入、check 模式与取消；实际导入处理 1 文档/1 分块，仅覆盖新 sandbox platform。
- [x] Pi 思考等级保存后刷新配置、Single/Multi 请求快照和 SQLite/DuckDB 文件导入完成浏览器回归；真实 Key UI 输入/Provider 探测仍未做。

## 4. 响应式和质量检查

- [x] 视口至少覆盖 320、390、768、1024、1440 px；无横向溢出、遮挡、按钮文字截断或输入区离开首屏。
- [x] 浏览器控制台无未处理异常；除预期取消外，失败网络请求均有解释并与测试记录一致。
- [x] 重复点击发送、停止、保存、导入不会产生重复任务或状态倒退；刷新后从后端会话历史恢复，不显示上一轮假成功。
- [x] 前端脚本通过 Node 语法检查，后端定向测试、`git diff --check` 和必要的 Playwright 回放通过。

## 5. 证据格式

每条通过记录：`时间、代码版本、模式、Provider/模型、数据源、请求摘要、session_id、结果摘要、截图/日志路径`。失败记录额外包含：`HTTP 状态、errorCode、errorMessage、复现步骤、是否外部配额问题`。

## 最终通过标准

- [x] Single/Multi 都能完成“问题 -> Agent -> SQL -> 数据库结果 -> 最终回答 -> 历史恢复”。
- [x] 前端展示与后端响应逐项一致，没有静态回答、静态 Token、静态连接状态或隐藏失败。
- [x] 桌面、移动端、正常、空、失败、取消、刷新和重试状态均有证据；反馈入口按用户要求排除。
