## 一、目标与硬性边界

- [ ] 保留并连接现有后端的真实能力，不伪造接口、数据、状态或统计。
- [ ] 后端路由、请求模型、响应模型和 SSE 协议作为功能范围的唯一事实来源。
- [x] 当前产品只保留 Single Agent 与 Multi Agent 两种运行路径；旧方案中的 Legacy 已从运行时契约下线。
- [ ] 保留现有有效能力，不修改后端核心业务规则。
- [ ] 后端不支持的功能必须删除、禁用或以明确空状态呈现。
- [ ] 所有可操作控件都必须有真实后端行为和完整成功、失败状态。
- [ ] 完成桌面端和移动端响应式实现及真实端到端验证。

## 二、已确认的产品方向

这是面向数据工程师的桌面工作台，不是营销页。视觉吸收 Anthropic / Claude 产品的温和、克制、可信赖和内容优先特征，同时保持数据工具所需的信息密度。

- `DESIGN_VARIANCE: 4`
- `MOTION_INTENSITY: 2`
- `VISUAL_DENSITY: 7`
- 默认亮色主题；本轮建立深色 Token，但不在未完整验证前暴露主题切换。
- 主强调色只使用陶土色；成功、警告和错误色仅承担语义状态。
- 主体依靠留白、分隔线和背景层级组织，不堆叠同质化卡片。

## 三、后端能力基线

| 能力 | 真实接口或协议 | 当前结论 |
|---|---|---|
| 流式 AI / NL2SQL 对话 | `POST /api/v1/chat/stream` | 支持 SSE |
| 执行模式 | `runtime_variant: single / multi` | 支持；缺省为 `single`，其他值返回 HTTP 422 |
| 停止与恢复 | SSE 请求中止；TaskManager stop/resume API | Single/Multi 支持停止，不支持恢复未完成生成；独立兼容流程保留 API |
| 会话管理 | sessions、history、delete、compact | 支持 |
| 用户补充输入 | `POST chat/user_interaction` | 支持 |
| 回答反馈 | `POST chat/feedback` | 支持 SSE |
| SQL 执行与停止 | `POST sql/execute`、`POST sql/stop_execute` | 支持 |
| Catalog 浏览 | `GET catalog/list` | 支持 |
| 表结构详情 | `GET table/detail` | 支持 |
| 语义模型 | semantic_model GET、POST、validate | 支持 |
| Explorer | `/subject/*` | 目录、指标、Reference SQL、Knowledge 可管理 |
| Agent | list、detail、create、edit、tools | 不支持删除 |
| MCP | servers、connectivity、tools、filters、call | 支持 |
| 知识库初始化 | `/kb/bootstrap*` | 支持 SSE 和取消 |
| 模型与系统配置 | `/models`、`/config/*` | 支持读取、更新和连通性测试 |
| 可视化推荐 | `POST data_visualization` | 返回图表推荐，不负责前端渲染 |
| WebSocket | 未发现 | 本次不实现 |
| 独立 SQL 查询历史 | 未发现 | 本次不实现 |
| 服务端表格分页与排序 | 未发现 | 本次不伪造 |
