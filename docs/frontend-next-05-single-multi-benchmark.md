# Single/Multi 量化评测清单

> 目标：用同一模型、同一题集、同一数据库和同一执行预算，量化 Multi Agent 相对 Single Agent 的真实收益。Legacy 不进入当前实验。

## 1. 实验控制变量

- [ ] 冻结代码 commit、Prompt、Pi 版本、Provider/model、思考等级、超时、最大轮次、工具集和数据库文件 hash。
- [ ] 使用 `benchmark/semantic_layer/testing_set_v2.csv` 或冻结后的题集；每题有 `case_id`、难度、能力标签、参考 SQL 和预期结果。
- [ ] 两种模式只改变 `runtime_variant`；请求顺序随机化，使用独立 session，失败和超时保留，不从分母删除。
- [ ] 正式实验按每题每模式至少 3 次重复：24 题 × 2 模式 × 3 次 = 144 次请求；若预算不足，先跑一轮烟测，再决定是否扩大重复数。
- [ ] 真实模型请求与确定性回放分开标记；回放只能验证前端解析，不能作为准确率或延迟结论。

## 2. 指标定义

### 结果质量

- [ ] SQL 正确率：生成 SQL 执行成功且结果与参考结果集等价。
- [ ] 完成率：SSE 在超时前有最终回答并正常结束；工具失败但最终可恢复时按规则单独统计。
- [ ] 最终回答有效率：回答包含与结果一致的结论，不把过程文本或错误当成答案。
- [ ] 分层准确率：按基础、关联、时间、复杂和能力标签分别统计，不能只报总平均。

### 效率和成本

- [ ] 端到端延迟：中位数、P95、超时数；按成功/失败分别保留分布。
- [ ] 模型请求次数、输入/输出/缓存 Token、总 Token、工具调用次数和失败重试次数。
- [ ] 若 Provider 提供价格，计算单题成本和总成本；没有价格时报告 Token，不猜金额。
- [ ] Multi 的额外开销与收益同时报告，不能只展示准确率。

### 稳定性和可解释性

- [ ] 重复运行一致率：同题同模式结果集等价的比例。
- [ ] 错误分类：模型/配额、SSE、工具、SQL、数据源、超时、前端解析和配置错误。
- [ ] Multi 轨迹：参与的子 Agent、工具链、审查/调试节点和失败位置；Single 记录对应工具链。

## 3. 执行和判分

- [ ] 扩展 `scripts/run_pi_benchmark.py` 或现有 runner，只接受 `single|multi`，把请求参数、原始 SSE 摘要和脱敏错误写入 JSONL。
- [ ] 扩展 `scripts/compare_pi_variants.py`：自动执行只读 SQL、比较结果集、汇总分层指标、计算重复稳定性和 p50/p95。
- [ ] 生成逐题明细、模式汇总、失败分类和可复核的原始证据索引；不保存 Key、Authorization、完整隐私路径。
- [ ] 人工复核自动判分边界：NULL、排序不敏感结果、浮点误差、空结果、SQL 语义等价和最终回答事实一致性。
- [ ] 记录外部 Provider 403/配额/网络故障并与 Agent 能力失败分开；必要时整轮作废并重跑，不能静默剔除。

## 4. 最终报告

- [ ] 报告至少包含样本量、控制变量、题集分层、准确率、完成率、延迟、Token/成本、稳定性、错误分类和限制。
- [ ] 结论使用“Multi 相对 Single 提高/降低 X 个百分点或 X%”，同时给出分母、置信区间或重复波动范围。
- [ ] 如果 Multi 只提高完成率但降低准确率，明确写出权衡；不使用单一综合分掩盖回归。
- [ ] 将当前报告与 Legacy 历史报告分开，README 和产品文档只引用 Single/Multi 当前结果。

## 通过标准

- [ ] 144 次请求（或明确记录的缩小实验）都有可追溯 case、mode、repeat、session 和结果状态。
- [ ] 自动判分和人工抽查结论一致；失败样本没有被删除或改写。
- [ ] 报告可在没有凭据的情况下理解方法并由有凭据的开发者复现。
